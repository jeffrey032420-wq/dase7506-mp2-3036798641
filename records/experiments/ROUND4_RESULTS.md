# 第四轮：新特征、多折验证与树排序器

日期：2026-10-14。**本轮仍未超过 744/798（93.23%），保留第二轮模型。**
当前推荐：`code/method_round2.py` + `code/runs/round2/model_bundle/`。
所有新方案的参数选择使用训练集内部数据；本轮没有计算测试集成绩。

## 统一的三折开发协议

将 4,755 道训练题按种子 20261018 分成三折，每折 1,585 题；用其余两折训练，
在该折产生预测。每道训练题的折外预测均来自没有训练过该题的模型。
同一道题的四个候选保持在一起。所有标准化、词表、IDF 和 PCA 都在各折训练部分拟合。
搜索先固定网格，参数按合并后的折外成绩选择，再用完整训练集重训并到官方验证集比较。

折外成绩仍参与参数/训练轮次选择，因此是开发指标，不能称作独立、无偏的泛化估计。
验证集又经历了一轮比较，最高验证成绩同样包含多次选型的乐观偏差。

## 新特征与消融

新增 24 个算术/关系特征，包括可解析等式的对错比例、答案符号和量级、题目数字覆盖率、
答案是否能由题目中两个数经基本运算得到、候选答案支持数等。
这些是软特征，不是答案正确性的证明。比如等式本身正确，也可能套用了错误的题意。

解析器只允许有界数字常量和四则运算，通过 AST 白名单解释，不能执行候选文本。
针对分数、负数、非法运算和带变量的表达式进行了专门检查。
初版曾把 `2x + 3 = 7` 中的数值片段误作完整等式；已修正并完整重跑。
初版记录保留在 `code/runs/round4/`，已标注过期；正式新特征结果来自 `round4-fixed/`。

文本特征使用训练折内选出的 384 个词/相邻词组，计算 log-TF × IDF。
比较原始上下文特征、加入算术特征、再加入文本特征三组；每组正则 alpha 搜索
{0.03, 0.3, 3}。三折共 27 次拟合配置评分。

| 方案 | 所选 alpha | 训练折外答对 / 4,755 | 验证答对 / 798 | 验证准确率 |
|---|---:|---:|---:|---:|
| 第二轮上下文模型 | 0.3 | 4,300 | **744** | **93.23%** |
| 加算术与关系特征 | 0.3 | 4,330 | 740 | 92.73% |
| 再加文本特征 | 3 | 4,329 | 735 | 92.11% |
| 算术/文本模型各占一半 | 分别使用上行配置 | 4,341 | 740 | 92.73% |

最后一项从七个预定义单模型/平均组合中，仅按训练折外预测选择。
官方复核融合方案修正旧模型 7 题，但新增 11 道错误。训练交叉验证的提升没有稳定
延续到官方验证集。不能把这一结果归因为已被证明的某个原因。

## PCA 二次关系与融合

另外比较从训练折拟合 16/32 维白化 PCA，并加入各维度之间的二次项及同题上下文项。
维度和 alpha={0.03,0.3,3} 共同按三折成绩选定，只将一个所选模型拿到官方验证集。

所选 16 维、alpha=0.3：训练折外 4,319/4,755，验证 733/798（91.85%）。
随后在原模型、算术、文本和 PCA 四个模型上，按 0.25 为步长的 35 个凸组合，
仅用训练折外预测选择融合权重。所选权重为 [0,0.5,0.25,0.25]：
训练折外 4,343/4,755，验证 740/798（92.73%），仍未超过旧模型。

## 梯度提升树排序器

使用 LightGBM LambdaRank，每道题是一组，标签为各候选是否符合官方数值答案。
只用本地训练数据训练，不使用预训练权重。输入为原始向量/文本特征、同题均值差向量、
算术关系特征；树可以学习这些特征之间的条件关系。

比较每棵树 7/15 个叶子，三折内以选择准确率早停（最多 400 轮，耐心 40 轮）。
叶数由训练折外总成绩选择，最终训练轮数取所选叶数三个最佳轮数的中位数。
其余参数与 LightGBM 版本已完整记录在 search-plan.json 和 checkpoint 配置中。

- 所选 7 叶子、51 轮：训练折外 4,330/4,755；验证 734/798（91.98%）。
- 对树分数与旧模型分数，使用训练折外题内分数 RMS 做缩放，从树权重
  {0,0.25,0.5,0.75,1} 中选型；平分优先较低树权重。
- 所选 25% 树 + 75% 旧模型：训练折外 4,330/4,755；验证 736/798（92.23%）。
- 该融合的统计缩放参数仅由训练折外分数估计，随配置一起保存，推理不依赖输入批量大小。

## 复现命令

从 `code/` 运行。环境为 Python 3.12，基础 NumPy 2.5.3。
树实验的新增依赖和确切版本单列在 requirements-trees.txt，原始官方依赖文件保持不变。

```powershell
.\.venv\Scripts\python.exe check_math_features.py
.\.venv\Scripts\python.exe train_round4.py --output runs/reproduced-round4-fixed
.\.venv\Scripts\python.exe train_round4_pca.py --output runs/reproduced-round4-pca
.\.venv\Scripts\python.exe -m pip install -r requirements-trees.txt
.\.venv\Scripts\python.exe train_round4_trees.py --output runs/reproduced-round4-trees
```

融合脚本 `select_round4_fusion.py`、`select_round4_tree_fusion.py` 默认从本次
`runs/round4-fixed/`、`runs/round4-pca/`、`runs/round4-trees/` 读取折外预测和候选模型。
它们拒绝覆盖已有选择；重做完整融合时应在独立项目副本中使用这些默认目录。

独立评估工具 `evaluate_candidate.py` 可对任意新方法运行官方验证评分及接口检查，例如：

```powershell
.\.venv\Scripts\python.exe evaluate_candidate.py --method method_round4.py --checkpoint runs/round4-fixed/model_bundle --output runs/round4-fixed/evaluation
.\.venv\Scripts\python.exe evaluate_candidate.py --method method_round4_pca.py --checkpoint runs/round4-pca/model_bundle --output runs/round4-pca/evaluation
.\.venv\Scripts\python.exe evaluate_candidate.py --method method_round4_fusion.py --checkpoint runs/round4-tree-fusion/model_bundle --output runs/round4-tree-fusion/evaluation
```

接口检查涵盖新 ID、1/7/23 题输入、候选重排、空输入，以及与官方独立进程预测一致。
对应官方 JSON 和检查结果保存在各目录的 evaluation/ 下。

## 当前判断

本轮增加了不同的信息来源和模型类型，并用三折取代单一留出集筛选，但仍未突破
第二轮的验证成绩。后续研究应以可检验的错误假设和完整对照为依据；继续试验不等于
必然提高泛化能力，也不能保证最终测试准确率等于当前验证准确率。
