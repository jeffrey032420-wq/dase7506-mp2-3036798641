# 第五轮：训练目标、核特征、文本扩展与候选重组

日期：2026-10-14。**本轮没有超过现有的 744/798（93.23%），继续保留第二轮模型。**
推荐方法仍为 `code/method_round2.py`，checkpoint 为 `code/runs/round2/model_bundle/`。
本轮没有生成测试集预测或计算测试集成绩。

## 选择协议

沿用种子 20261018 的训练集三折划分，每折 1,585 题，同题的四个候选保持在一起。
标准化、核中心、词表、IDF 和协方差变换都只在各折的训练部分拟合。
候选重组也仅使用训练折内的题目和标签，不向持出折添加重组样本。

各子实验先写出搜索计划，再按合并后的训练折外正确数选择配置，完整训练集重训后
到验证集比较。共记录 171 个折内配置评分，另比较 35 组固定融合权重。
验证集比较了八个冻结配置，其中融合配置退化为已有的相对核模型。
折外结果参与了选型，验证集也已被多轮反复使用；两者均是开发指标，不是独立测试估计。

## 方法和观察

### 1. 难题加权与间隔损失

对仅有一个正确候选的训练题赋予 {1, 2, 4} 倍权重，alpha 搜索 {0.1, 0.3, 1}。
每题内部的正确—错误候选对仍平均加权，总损失按题权重和归一化。
比较平方损失与平方 hinge 损失；后者不再惩罚已超过目标的正确分差。
两种目标均选中权重 2、alpha 0.1，但验证难题答对数均停留在 70。
平方损失修复了旧模型的 6 个错误，同时引入 11 个新错误。

### 2. 核特征

在原始上下文特征上加入 512 个 RBF 响应，中心从训练候选中随机抽取。
比较绝对嵌入和减去同题平均嵌入后的相对表示。
核宽度为训练候选距离中位数的 {0.25, 1, 4} 倍，alpha 为 {0.03, 0.3, 3}。
两种模型各占约 4.81 MiB，但验证集均没有修复旧模型的任何错误，分别新增 2 和 4 个错误。
在本次比较中，新增复杂度没有带来有效互补。

### 3. 扩大文本覆盖

词和相邻词组词表最多 25,000 项，最低文档频次 3；使用 log-TF × IDF 后做行 L2 归一化。
与原始上下文特征联合拟合，文本幅度搜索 {8, 32, 128}，alpha 固定 0.3。
使用稀疏 LSMR 求解，容差 1e-7，上限 400 次迭代，并要求收敛。
较大的文本幅度明显降低训练折外正确数，选中的幅度为 8。
推理只需 NumPy，资产约 1.61 MiB。复核时修复了逐词重复加载 NPZ 权重数组的性能问题；
现在权重只加载一次，计算公式和预测结果不变。初次训练总耗时包含修复前的验证推理开销。
修复前后的 798 个选择逐项一致；新鲜预测进程加独立评分的本地耗时从 32.96 秒降至
1.40 秒，记录见 `code/runs/round5-verification/text-performance-fix.json`。

### 4. 候选重组

每道有正负候选的训练题随机选择一个正确和一个错误候选，复制成 1:3、2:2、3:1 三种组合。
保持文本、嵌入和标签对应，并在每个重组内重新计算一致性和上下文特征。
这会改变候选支持数，而不引入外部数据或新的语言模型输出。
增强损失权重搜索 {0.25, 1, 4}，alpha 搜索 {0.1, 0.3, 1}。
选中的增强权重为 1、alpha 0.1；折外有所改善，但验证下降到 735。
因此不能据训练折外结果宣称已经获得泛化收益。

### 5. 白化与融合

白化方案先在训练嵌入上拟合 PCA，保留 {32, 128, 512} 维并按特征值白化，
再随机投影到 96 维构造原有上下文特征。原始线性特征仍保留。
选中的维度为 512、alpha 0.3，验证结果为 731。

融合使用原模型、两种核模型、文本模型的同折外分数，比较权重为 0.25 整数倍、
总和为 1 的 35 种配置。并列时优先较少成员。最优配置只保留相对核模型，
没有获得额外收益。融合选择在候选重组和白化实验之前完成。

## 资源、复核与保存

- CPU：本机 Intel Core i5-11400H；训练和评估设置为四线程。
- 训练：Python 3.12.14、NumPy 2.5.3、SciPy 1.18.1；推理只需 NumPy。
- 所有新 checkpoint 均小于 16 MiB。权重、配置、搜索记录及种子已保存。
- 复核包括官方进程结果一致性、新 ID、不同 bank 大小、候选换序和空输入。
- 官方工具和第二轮 checkpoint 的 SHA-256 完整性检查保存在
  `code/runs/round5-verification/integrity.json`；各模型资产哈希在对应 `verification.json`。
- 本轮各训练脚本合计约 430 秒，包含搜索、重训及初次验证打分；主机负载会影响耗时。
- 最新本地验证耗时见 `code/runs/round5-verification/results.json`。
  第二轮模型本次复核为 0.98 秒，本轮新方案为 0.96–1.40 秒。
  它不是完整测试集在官方参考 CPU 上的资格认定。

## 复现

从 `code/` 运行，先按 `requirements-training.txt` 安装训练依赖：

```powershell
.\.venv\Scripts\python.exe train_round5.py
.\.venv\Scripts\python.exe train_round5_kernel.py
.\.venv\Scripts\python.exe train_round5_text.py
.\.venv\Scripts\python.exe select_round5_fusion.py
.\.venv\Scripts\python.exe train_round5_augment.py
.\.venv\Scripts\python.exe train_round5_whiten.py
.\.venv\Scripts\python.exe verify_round5.py
```

融合还需要第四轮的 `runs/round4-fixed/out-of-fold-scores.npz`；其生成命令见
`ROUND4_RESULTS.md`。只复核冻结模型时不需要重训，但需要保留全部对应 checkpoint。
第四轮和第二轮的资产仍原样保留，`CURRENT_BEST.json` 指向最终推荐的开发模型。
